Try it

Type a name, press the buttons, type any six digits for the code.

1 · A link to a public call

Someone sends a link. The page asks for a name and nothing else. It never offers the app and never tries to open it.

  1. One field, one button. The face fills in as the name is typed, as on the Mac's first launch. The headline says who invited you, not a room type.
  2. Microphone on, camera off when the page opens. The browser asks for the microphone when Join is pressed; if the answer is no, the call still opens, muted, with a line saying how to allow it. Turning the camera on shows it in the circle first.
  3. Gone from this page: Open in the Mac app, Get the Mac app, the device pickers, the microphone meter, the “1-to-1 call / public room” label, the note about claiming a link, Back to Cubie. A second microphone or camera gets one quiet “Change microphone or camera” line, only when there is more than one.
  4. Coming back is one tap: the name is remembered in this browser.

2 · An invitation to a private call

Private calls need an account, so the invitation is also the way to get one. Email, six digits, name, in.

  1. The invitation is the registration. Today a private room invitation needs a second, separate account invitation from an admin. Here whoever is invited to a private call can make their account from that link. Cubie stays invite-only: there is still no way to sign up without someone inviting you.
  2. A code typed where you asked for it. No “return to the tab you came from”. The email also has a button for people reading it on the same device; it lands on the same next screen.
  3. The name is asked once, on the screen with the Join button, and only if the account has none. Someone who already has an account goes email, code, Join.
  4. One kind of invitation to explain: “Each link works for one person.” An invitation made for a particular email only accepts that email.

3 · Signing in on the website

cubiecall.com with no link: the same two screens, then your rooms.

  1. Home is one button and a list. Start a call makes a link to send; the people who open it are in flow 1.
  2. A room's page keeps what the old page did (rename, invite, people, close) as a plain list. A private room has one Invite action.
  3. No account? The page says the same thing either way, as today, so nobody can test which emails have accounts. “Didn't get it?” explains that Cubie is invite-only.

4 · Signing in in the app

The app stops sending people to the browser. Email and a code, in the app's own window. On iPhone the code fills itself in from Mail.

  1. Today: the app opens a browser, the browser needs its own sign-in (email, a link in a new tab, back to the first tab), then an 8-character code is read off the app and typed into the page. New: two screens in the app.
  2. The email for the app has only the code, no button: a button would sign in the browser, not the app.
  3. The name window stays as it is and shows only for a new account.
  4. Home's account row opens a small menu (your name, email, Change name, Sign out) instead of the buttons and the code that sit in the sidebar today.
  5. Apps already installed keep working: their browser page stays, restyled (see 5).

5 · Everything else

The cases around the four flows. Each is one sentence and one button.

What changes underneath

  1. Sign-in email: a 6-digit code (five tries, 15 minutes) next to today's link. The link's page keeps its one button (mail scanners open links, and a link that signed in by itself could be used up before you see it), restyled as “Continue to Cubie”, and then goes on to the call you were invited to.
  2. Private invitations create accounts. A room invitation counts as an invitation to Cubie for one person. Admin invitations stay for inviting someone without a room.
  3. Private rooms need an account. No more name-only guests in private rooms; people who already joined that way keep their access.
  4. The join page learns who invited you (the owner's first name), only where the room's name is already shown.
  5. Apps sign in with email and code. The browser approval stays on the server for builds already installed.
  6. New accounts start without a name (today it is the part of the email before @) and are asked once.
